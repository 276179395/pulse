# 自定义“在此处打开终端”交接记录

更新时间：2026-10-29（Asia/Shanghai）。

## 目标与已确认边界

用户采用两步走方案：

1. 在设置中允许用户选择右键目录“在此处打开终端”使用的终端程序。
2. 第一阶段确认后，再设计终端别名映射，并考虑地址栏调起。

当前只实现第一阶段原型。地址栏输入 `wt`、`cmd`、`powershell`、`pwsh` 的解析和启动规则保持原样。

## 已完成

- 设置 → 文件操作增加“在此处打开终端”配置卡片。
- 通过文件选择器选择 `.exe`；取消选择保留当前配置。
- 显示当前程序路径；长路径省略显示，悬停提示完整路径。
- 可以恢复默认 Windows Terminal；默认状态禁用恢复按钮。
- 新增 `AppPrefs::terminal_program` 并保存到 `app.json`；空值代表默认 `wt.exe`。
- 旧配置缺少该字段时保持原默认行为；恢复全部设置会清空自定义终端。
- 右键终端请求将所选程序复制进后台队列；启动过程仍在现有打开工作线程上执行。
- 自定义程序默认不附加参数，以目标目录作为工作目录启动。
- 默认或文件名为 `wt.exe` 的自定义 Windows Terminal 使用 `-d` 参数。
- 右键路径中包含分号时，新的终端辅助函数使用 `-d .` 和目标工作目录，避免将目录名作为 WT 命令分隔符传入；真实 WT 场景仍待验证。
- 新增程序字段校验，只将它作为可执行程序名称/路径处理，不提供命令模板。
- 中文、英文、繁体文案在 `tools/l10n/catalog.tsv` 中新增，已运行生成器；没有手改生成内容。
- 加入启动、偏好保存和真实设置渲染器的定向测试。

共享“在此处打开终端”动作的目录菜单、面包屑/侧边栏路径菜单和详情菜单均传入同一配置；既有工具栏若使用同一动作，也会使用该配置。地址栏的 `OpenProgramIn()` 分支没有改动。

本版没有实现：自由参数输入、别名映射、终端配置列表、自动枚举 Windows Terminal profiles、WSL 路径转换、终端自动发现。

## 验证边界与待办

这是一版可供继续评估的实现，不应仅凭构建和测试通过就认定所有终端均兼容。

换设备后优先做以下人工验证，并记录实际结果：

1. 打开设置 → 文件操作，确认默认状态、选择程序、取消和恢复默认的交互。
2. 选择本机已安装的终端，右键目录启动，确认程序和工作目录；重启 Pulse 后确认配置保留。
3. 验证默认 WT、指定绝对路径的 WT，以及包含空格、中文、分号和盘符根目录的真实启动。
4. 按需验证 UNC、长路径、真实 UAC 和用户取消；现有对应自动化主要验证接口/参数或模拟结果，不能当作真实终端兼容性验证。
5. 不同终端可能自行覆盖工作目录，CMD 对 UNC 也有自己的限制。首版只设置进程工作目录，尚未为所有终端做专用适配。
6. 实际确认地址栏调起不受设置影响；现有解析回归已通过，但尚未做地址栏真实启动的人工回归。
7. 对本次 diff 做最终 PR 审查，再决定提交上游；不要顺手修复上游无关问题。

第二阶段应等用户确认第一阶段后再开始：先定义别名的数据结构、默认项、名称冲突规则及参数规则，再接入地址栏。不要把第二阶段自动并入当前 PR。


阅读本文件、[代码与验证说明](IMPLEMENTATION.md) 和根目录 `AGENTS.md`。先检查 `git status`，保留任何新的未提交修改。

本机曾在受限执行环境中遇到原生测试异常退出和 CMake 编译器检测无法完成，普通本机环境验证成功。首次构建从空 `build` 开始，涉及主程序依赖；没有可靠的设备性能基准数据，不能据此断定设备需要升级。
